# Branching- und Commit-Konvention

## Branching-Modell

### Hauptbranches
- `main` – stabiler Hauptstand
- optional `develop` nur dann, wenn Team- und Release-Komplexität steigt

### Arbeitsbranches
Namensschema:
- `feature/<kurzname>`
- `fix/<kurzname>`
- `docs/<kurzname>`
- `refactor/<kurzname>`
- `chore/<kurzname>`

## Commit-Konvention

Empfohlen wird ein leichtgewichtiges Conventional-Commit-Schema:

- `feat:`
- `fix:`
- `docs:`
- `refactor:`
- `test:`
- `chore:`
